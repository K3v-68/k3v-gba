## RTC audit and fixes

The synthesized PLL configuration, rather than its legacy signal name, is the
clock authority. `mf_pllbase_0002.v` generates the GBA system clock at exactly
`100,663,296 Hz` (`6 * 2^24`). The upstream divider used 100,000,000 cycles, so
its uninterrupted clock ran 1.00663296 times real time (about 573.09 extra
seconds per day). That measurable error does not by itself explain a reported
near-2x observation, so no crude divide-by-two correction was introduced.

The old design also treated both transitions of a synchronized Pocket RTC
notification as new, fast-forwarded elapsed seconds through the live calendar
state machine, exposed intermediate catch-up state, omitted leap-day handling,
and accepted an incompletely validated persisted footer.

The replacement RTC:

- captures only the first Pocket epoch/BCD notification after configuration;
- validates the complete 16-byte footer (epoch, packed BCD calendar, reserved
  bits, and six padding bytes);
- preserves a valid persisted calendar if the host clock moved backwards and
  clamps elapsed time to zero;
- computes elapsed time in shadow registers with bounded day/hour/minute
  subtraction, then atomically commits calendar and epoch once;
- uses a terminal count of 100,663,295 for exactly one tick per 100,663,296
  system-clock edges;
- implements 2000..2099 leap years, month/year/weekday rollover, S-3511 reset,
  full and time-only writes, writable status masking, and the documented
  S-3511A `00..11 + AM/PM` / `00..23` hour encodings;
- captures a complete GPIO write on the final serial-bit edge behind a preserved
  register boundary, while time-only writes retain the live decoded date inside
  the RTC; this keeps write-over-tick priority exact without recreating the
  serial-decode timing path;
- leaves wall-clock state outside gameplay save-state restore, so loading a
  gameplay state cannot rewind the RTC.

RTC games remain held in reset until the one-time shadow initialization has
committed.

## Save-path audit and fixes

The upstream unloader sampled PSRAM after a fixed cycle delay instead of waiting
for `read_avail`. A delayed/busy PSRAM access could therefore place the default
or stale word into the Pocket response FIFO. The RTC footer was generated by a
separate mux, matching the reported failure signature of an all-zero 128 KiB
body with an intact final 16-byte RTC extension.

The repaired path uses request/ready and response/valid handshakes across the
clock-domain FIFOs. Addresses and requests remain stable until accepted, a
response FIFO write occurs only after actual memory validity, and the APF bridge
stalls until the complete 32-bit response exists. A missing PSRAM response can
no longer be converted into zero data.

All four PSRAM clients (boot loader, erased-tail fill, Pocket unloader, and live
GBA save bus) are mutually excluded through explicit grant conditions. Pocket
unload pauses new CPU/DMA work, drains queued flash program/sector/chip-erase
operations, and waits for the GBA memory sequencer plus PSRAM controller to be
idle before the first read. Completion pulses cannot be attributed to another
client.

The PSRAM controller captures every accepted address, bank, byte enable, and
write word before driving the device pins. A registered transaction-start pulse
then begins the physical cycle, while a small independent counter generates the
specified ADV# pulse. This removes the wide controller-state decode from the
ADV# output timing path without changing the external read/write cycle lengths.

Save loading now:

- accepts only sequential, recognized complete sizes;
- supports 512-byte/8 KiB EEPROM, 32 KiB SRAM, 64 KiB Flash, and 128 KiB Flash;
- fills the unused tail of legitimate smaller imports with `0xFF` before
  gameplay, preventing retained PSRAM from leaking into a normalized save;
- rejects partial/out-of-order loads by keeping the core in reset and disabling
  unload, rather than exposing them to Pocket writeback;
- waits for the final physical PSRAM write, not merely FIFO acceptance, before
  finalization;
- snapshots the RTC footer at the start of a save stream to avoid a torn tick.

## Automated verification

`tests/rtc` contains an independent Python reference and a self-checking
VHDL-2008 testbench. It covers exact divider phase, uninterrupted 1 second,
10 minutes, 1 hour, and 24 hours; powered-off catch-up; duplicate initialization;
month/year/weekday/leap rollovers; host rollback; persisted restart; game write;
RTC reset; invalid input defense; and collision priority.

`tests/save` contains a behavioral asynchronous FIFO plus a self-checking
SystemVerilog unloader testbench. Full mode compares patterned, deterministic
random, and all-`FF` 128 KiB fixtures byte-for-byte under unrelated clocks,
random and long ready/response latency, and busy conditions. A separate
unanswered-response case proves that the bridge remains stalled without
fabricating zero or stale data.

`tests/psram` contains a self-checking pin-level controller testbench. It proves
that `busy` is asserted at acceptance while physical pins wait for the registered
start stage, accepted inputs remain latched if live inputs change, ADV# has the
configured pulse length, read/write pins and byte enables match the accepted
request, responses arrive with the expected handshake, and a conflicting
request is ignored while busy.

Project-level validation additionally parses every shipped JSON document,
regenerates and checks the 36x36 Pocket icon, verifies the shared platform-image
dimensions, creates the package ZIP twice to prove byte-for-byte determinism,
and rejects any archive entry below `Cores/` that is not below
`Cores/K3V.GBA/`. This prevents unrelated local core directories from leaking
into a K3V release.

The Pocket core icon is original K3V artwork generated for this project. The
shared `Platforms/_images/gba.bin` is intentionally preserved because Pocket
platform artwork is shared by every installed GBA core, rather than owned by a
single core package.

## Synthesized release candidate

The release image was compiled from a clean, local non-OneDrive workspace with
Quartus Prime Lite 21.1.1 Build 850, Standard Fit, and seed 9 for Cyclone V
`5CEBA4F23C8`. Seed 8 missed one slow-corner setup path by 0.001 ns and was
therefore rejected; seed 9 closes every analyzed timing check without changing
the logic netlist. The final fit uses 17,693 of 18,480 ALMs (96%), 278 of 308
RAM blocks (90%), and 26 of 66 DSP blocks (39%).

TimeQuest reports zero negative-slack paths and TNS `0.000` at every analyzed
corner. The worst system-clock setup slack is `+0.094 ns` at the slow 1100 mV
85 C corner and `+0.088 ns` at the slow 1100 mV 0 C corner. The smallest hold
slack in the complete summary is `+0.076 ns` at the fast 1100 mV 0 C corner.
The design is fully constrained for both setup and hold.

The raw Quartus RBF is 2,107,552 bytes. The packaged `bitstream.rbf_r` has the
same length and is verified byte-for-byte as the bit reversal required by the
Analogue Pocket loader. Pre- and post-build SHA-256 manifests prove that every
synthesis input remained unchanged throughout the 22-minute compilation.

The complete Quartus log and custom TimeQuest reports are written below
`build_output/`; the deterministic release ZIP, SHA-256 sidecar, and machine-
readable source/toolchain/evidence manifest are written below `dist/`.
